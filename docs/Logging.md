# Logging

Structured, Persian-language logs via **Serilog**. Every entry is keyed by the
correlation id so a single business operation can be traced end-to-end across
the API, the worker, the broker and the consumers.

## Stack

- **Serilog.AspNetCore** as the host logger.
- **Serilog.Sinks.Async** + **Console** (dev) — high-throughput async writes
  with `InvariantCulture` formatting so numeric fields never vary by locale.
- Enrichers: `WithMachineName`, `WithEnvironmentName`, `WithThreadId`,
  `FromLogContext` (scopes).

## Standard fields

Every log entry carries:

| Field | Source |
| --- | --- |
| `CorrelationId` | `X-Correlation-Id` header or generated by `CorrelationIdMiddleware` |
| `RequestId` | per-inbound-message unique id |
| `TraceId` | `HttpContext.TraceIdentifier` (or W3C traceparent) |
| `TransactionId` | added by handler scopes when the topup id is known |
| `MobileNumber` | included where the handler logs it explicitly |
| `ElapsedMilliseconds` | from `LoggingBehavior` / `PerformanceBehavior` / `RequestLoggingMiddleware` |
| `UserIp` | `HttpContext.Connection.RemoteIpAddress` |
| `MachineName`, `Environment`, `ThreadId` | Serilog enrichers |

## Pipeline

`LoggingBehavior` opens a Serilog scope carrying the correlation / request /
trace ids and writes an entry/exit pair around every MediatR request.
`PerformanceBehavior` warns when a request exceeds 500ms.
`UnhandledExceptionBehavior` logs unexpected errors with full context.
`RequestLoggingMiddleware` emits one entry per HTTP request at the edge.

## RFC 7807

Unhandled exceptions are converted to `ProblemDetails` by
`GlobalExceptionHandlerMiddleware` with a stable `type` URL and the
correlation id in an extension, so clients can quote it in support tickets.
